# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

Interactive map of the fictional world "Eurth" — hover to highlight countries, click or tap to see stats (population, GDP, capital, etc.), and suggest a correction that the owner reviews (see Suggested edits). Works with mouse + keyboard and on phones and tablets (see Touch and small screens). Built with React + Vite, no map library. SVG overlays on a static raster background; one Vercel serverless function.

## Architecture

- `eurth-map/` — the React app (Vite)
  - `public/background.webp` — 8000x4000 base map WITHOUT its legend (**generated** by `overlay-tools/build_layers.py` from `Overlays/Eurth-Geography-Map-10-3-2026 No Legend.png`, itself made by `overlay-tools/strip_legend.py`, see Base map updates). `public/background.png` is the same image as PNG; only the review page reads it
  - `public/layers/` — toggleable overlay images and the two legends, all WebP (**generated** by `overlay-tools/build_layers.py`, see Map Layers)
  - `public/overlays.svg` — generated SVG of nation shapes. **Do not edit by hand** — rebuild with `overlay-tools/build_overlays.py`
  - `public/nations.geojson` — the same shapes in lon/lat, written by the same build (**generated, do not edit**). Loaded by the globe view
  - `src/components/MapViewer.jsx` — main component: loads SVG overlay via fetch, handles pan/zoom/hover/click/tap/pinch (see Touch and small screens)
  - `src/components/GlobeViewer.jsx` — globe.gl globe: the base map as the texture, `nations.geojson` as invisible polygons that take the nation's color on hover/select, same `NationPanel`. Lazy-loaded from `App.jsx` (three.js is ~540 KB gzipped); `App.jsx` holds the Flat map / Globe switch. The directional light follows the camera (globe.gl puts it above the north pole, which left the south dark). The highlight, the measure fill and the measure lines sit 0.03-0.05 units above the surface (`NATION_ALT` etc.; radius 100), low enough that they do not shift against the map when seen from the side (at globe.gl's usual 0.4 they did, since 2026-10-02). That height needs two things: caps tessellated every 1° (`CAP_RESOLUTION`; coarser facets dip under the globe) and a camera near plane set before every frame to half the distance to the surface (`scene.onBeforeRender`; with globe.gl's fixed 0.05 the depth buffer cannot separate highlight and surface when zoomed out). In dev the instance is on `window.__globe`
  - `src/data/layers.js` — overlay list, stacking order and the legend rule (`imageLayers(enabled)`); `src/data/map-layers.json` is the generated legend position. `src/components/LayerToggles.jsx` — the bottom-left switches (above the Flat map / Globe switch, clear of the nation panel): the image overlays, then an "Organizations" group (see International organizations); the on/off state lives in `App.jsx` so it carries over between views
  - `src/data/organizations.js` — international organizations (`id`, `name`, `color`, `members` = `nations.js` keys) and `memberColors(enabled)`, the `{nationKey: [colour, ...]}` map both viewers highlight from. `src/utils/stripeMaterial.js` — the globe's striped fill for a nation in several organizations (imports three.js, so only `GlobeViewer.jsx` may import it)
  - `src/data/climates.js` + `src/utils/climate.js` + `src/hooks/useClimateReadout.js` + `src/components/HoverTooltip.jsx` + `src/components/ClimateCard.jsx` — the climate readout (see Map Layers): the 19 Köppen zones with their map colours and Wikipedia pages, the pixel sampler, the shared hover / long-press state, the tooltip that follows the pointer (nation name and/or zone; both viewers place it through `ref.moveTo(clientX, clientY)`), and the fixed card with the link
  - `src/hooks/useMeasurement.js` + `src/components/MeasureControls.jsx` — measure-mode state, math and readout shared by both views. Points are always map pixels; each viewer only converts clicks to map pixels, hands them to `addPoint(point, screenXY)` and draws `drawn` (lines), `markers` (points) and `rings` (area fills), each item carrying its measurement's `color`. **Several measurements can be on the map at once** (since 2026-10-01): a double-click / double-tap (second click within 400 ms and 8 screen px, detected in the hook so both views agree) **finishes** the one being drawn, which stays on the map in its own colour (`MEASURE_COLORS`, six, the first one not in use) and is listed in the readout as "Route N" / "Area N" with its total and a × to remove it; the next click starts another, unconnected one. A double-click on a lone point keeps nothing. Undo / Backspace remove the last point, or reopen the last finished measurement when nothing is being drawn; Clear removes all of them. Distance/Area applies to every measurement at once. Esc still exits the tool, which clears everything. Next to "Exit measure" a "Hide options" / "Show options" button (since 2026-10-02, state in `MeasureControls.jsx`) folds the readout down to one line, the figure being drawn, so a phone keeps its screen for the map; folding clears nothing and points can still be placed
  - `src/hooks/useKeyboardPan.js` — WASD / arrow keys (by physical key, Shift = 2x) move the view in both viewers; calls `onStep(dx, dy, seconds)` once per frame while a key is held. Flat map: shifts `transform` at 900 screen px/s, then re-checks what is under the still pointer (the browser sends no `mouseover` when the map slides under it). Globe: changes `pointOfView` lat/lng at a rate proportional to altitude, latitude clamped to ±85°
  - `src/components/NationPanel.jsx` — side panel showing nation stats on click, with the "Suggest an edit" button; takes `nationKey` as well as the nation object
  - `src/components/SuggestEditForm.jsx` — the native `<dialog>` that button opens: the nation's five stored stats pre-filled and editable, plus optional handle and note; posts the changed fields to `/api/suggest` (see Suggested edits). Mounted only while open, so each opening starts fresh
  - `api/suggest.js` — Vercel serverless function behind that form: validates against `nations.js`, files a GitHub issue. Runs on Vercel and under `vercel dev`, never in `npm run dev`
  - `src/data/nations.js` — all nation data (population, gdppc, land area, capital, iiwiki link, optional highlight `color`). Includes database-only nations with no overlay yet (the 69 at the bottom come entirely from the secondary data); unknown values are `null` (panel shows "—"). `secondaryFields: [...]` on a nation lists the fields whose value came from the less-trusted secondary source (see Nation Data Sources); fields not listed are the user's vetted data
  - `src/data/traced-areas.json` — km² of each nation's traced shape, written by `build_overlays.py` (**generated, do not edit**). Nations with a hand-drawn part (Aurora) are left out; regions listed in `overlay-tools/area-exclusions.json` are drawn but not counted
  - `src/data/landArea.js` + `src/data/map-area-nations.json` — the single "Land Area" viewers see: the stated `landArea`, except for the nations listed in the JSON, which show the traced area. The list is kept by hand and is the only thing the code checks: there is no percentage threshold. It currently holds 9 nations: Rhodellia, Verraine, Kirvina, Charkov, Ionio, Tagmatium (from +182% to +5% against the stated figure; Bamraland left the list 2026-10-03 when its enlarged territory brought the traced area within 4% of the stated one), Volsci (+132%: it expanded on the 2026-10-03 map and the stated figure predates that) and Kalei and Tetlacatian (added 2026-10-03 with no stated figure), while others further off (Great-Anglia +119%, Florentia -70%) still show the stated one; `area-discrepancies.md` has every nation's figures. Viewers never see two figures
  - `src/utils/device.js` — `COARSE_POINTER` (the main pointer is a finger) and `IS_PHONE` (that, and a short screen side under 600 CSS px), decided once at load
  - `src/utils/geo.js` — pixel/lon-lat conversion, haversine distance, great-circle paths, spherical polygon area
  - `src/utils/format.js` — display formatting (population in millions, GDPPC rounded to nearest A$500, land area rounded to nearest 1000 km², GDP computed from raw numbers), plus `parseNum` / `formatNumInput` for the edit form (same number rule as the review page: "48 million", "1.2bn", "A$39,500" all parse)

## Build and Deploy

```bash
cd eurth-map
npm install
npm run dev          # dev server at localhost:5173, also reachable from a phone on the same Wi-Fi (Vite prints the Network URL). No /api: the suggest form fails here
vercel dev           # Vite plus /api/suggest at localhost:3000 (launch.json entry "eurth-map-vercel"). Reads eurth-map/.env (gitignored): SUGGEST_DRY_RUN=1 logs suggestions instead of filing them
npm run build        # production build to dist/
vercel --prod --yes   # deploy to https://eurth-map.vercel.app (project is linked via .vercel/; passing --scope fails with CLI 50.x)
```

Pushing to GitHub does not deploy: the Vercel project is not connected to the repository (checked 2026-09-28), so the live site changes only when `vercel --prod --yes` is run.

`SUGGEST_GITHUB_TOKEN` must exist as a Vercel production env var before a deploy for the suggest form to work on the live site (see Suggested edits); a deployment only sees the variables that existed when it was built.

`DEPLOY.md` (root) is the plain-language version of this section for someone other than the owner: build, a fresh Vercel project from a fork, the token, a custom domain and the origin check, other hosts, updating content. Keep it in step when the build or deploy changes.

## SVG Pipeline

`overlays.svg` is generated by script from raster maps. Nation shapes are no longer drawn in Affinity.

```bash
python overlay-tools/build_overlays.py     # rebuild overlays.svg, nations.geojson and traced-areas.json (~15 s)
python overlay-tools/review_server.py      # nation editor + border review page at http://localhost:5180
```

1. **Regions**: `build_overlays.py` reads `Eurth Blank Map Borders.png` (grey land, white borders/sea, 8000x4000) and adds the thin red border lines from `Eurth-Geography-Map-10-3-2026.png` (the blank map is out of date in places). Every enclosed patch of land becomes a numbered region (`overlay-tools/out/`).
2. **Nations**: `overlay-tools/nation-seeds.json` maps each `nations.js` key to `[x, y]` map-pixel points, one inside each region the nation owns (mainland, islands, exclaves). Regions are merged, traced and written as `<g id="KEY"><path/></g>`. A value of `"manual"` (currently Aurora, whose border is on neither map) copies the hand-drawn group from `overlay-tools/manual-overlays.svg` instead.
3. **Leaks**: flags and labels that sit on a border leave gaps, so a nation can bleed into its neighbour. Fix by adding a polyline to `overlay-tools/border-patches.json` (or "Draw border" in the review page). To locate a gap, run `python overlay-tools/find_leak.py X1 Y1 X2 Y2` with one map-pixel point on each side of the border that should separate them: it prints the width of the gap and every spot along the widest route between the points that is that narrow (since 2026-10-03; the route is only as wide as the gap, so it brushes other borders at the same clearance, and the gap is one of the listed spots, usually the one on the border that should separate the points; map labels sitting on the border are the usual cause). When a nation's whole new border is on the map, `border_course.py` along it is quicker: it lists every hole at once. Patch, rebuild, repeat until it reports different regions. Dark text (a nation's name, a city label) cuts the red line just like a flag does, and the blank map's coastline can sit a few px away from the geography map's, so run a patch a few px past both ends of the gap and into the sea when it should meet the coast; a patch that stops 1 px short of the red line leaves a 1-px hole. The three patches added 2026-09-22 close the gaps that Ealis's flag, Marcendy's name and Tabaristan's flag left. A **closed** patch carves an enclave out of another nation: the 12 px circle around the INB Ptelenos port icon at (2211, 2864) on Kirvina's north-west coast makes that land its own region, and Tagmatium's seed (2214, 2866) claims it (added 2026-09-22). That enclave is drawn but **not counted** in Tagmatium's traced area: `overlay-tools/area-exclusions.json` (`{nation: [[x, y], ...]}`) lists seed points whose region is left out of `traced-areas.json` and the area check; the build refuses a point that is not in that nation's own territory.
4. **Old borders on the blank map**: where the blank map's white border runs beside the red line instead of on it, the strip between them ends up unpainted or in the neighbour ("nation X does not reach its border"). List that stretch in `overlay-tools/border-erasers.json` (a polyline, or `{"line": ..., "width": px}`): the blank map's white pixels under the stroke become land again, only where land is close on both sides, and the red lines still apply. Erasing usually exposes holes in the red line that the old border was covering, so run `python overlay-tools/border_course.py X,Y X,Y ...` along the border first: it snaps the points to the red line, prints a patch for every hole (rivers, flags and labels drawn over the line) and the snapped line to use as the eraser. Keep an eraser clear of lakes and inlets: it fills any water narrower than 25 px. Fixed this way 2026-09-22: Welkija's north, Tavok's south-east, Ulfheimr's east, Neusrya's south-west, Dolchland's north.
5. The build prints an area check (stated km² vs traced area, latitude-corrected). Values far from 1.0x mean a wrong/leaking region or a generous stat.

To add a nation or give a database-only nation its territory, use the review page (`review.html` + `review_server.py`): search the nation list (filter "No territory yet") or "+ New nation" (short name → key via `make_key`, iiwiki link derived from it), "Click regions to assign", then Rebuild. The same editor sets the highlight colour — "Mark its flag on the map" (drag a box; the server snaps it to the flag's dark outline and saves it in `flag-boxes.json`) offers the flag's 2–3 main colours (k-means in `flag_colors`), plus a free colour picker — and edits the stats. Stats, colours and new nations are written to `nations.js` immediately; only territory and borders need Rebuild.

`legacy/extract_overlays.py` is the old Affinity-export cleaner; only needed to add more hand-drawn shapes to `manual-overlays.svg`. Always pass both paths: its default output is `eurth-map/public/overlays.svg`, which the build owns.

Highlight colors are not baked into the SVG. A nation's optional `color` in `nations.js` is applied as an inline `fill` in `MapViewer.jsx` and as the polygon cap color in `GlobeViewer.jsx` (`highlightColor`); nations without one fall back to the red `fill` in `App.css` / `DEFAULT_COLOR`. Every nation with an overlay has a color: some hand-picked, most picked from the nation's flag on the base map (flag share vs. contrast with neighbours; reasons in `nation-colors.md`). `overlay-tools/flag-boxes.json` holds the `[x, y, w, h]` of the flags on the map; a flag the map update moved or redrew needs its box re-snapped (`snap_flag_box` in `review_server.py`), or the review page offers the colours of whatever is under the old box. The review page paints regions in these colors and lists flag + swatch per nation.

## Base map updates

The world map is re-issued now and then (last: `Eurth-Geography-Map-10-3-2026.png`, 2026-10-03, replacing the 5-29 map). What a new issue takes, in order:

1. Put the new PNG (8000x4000, with legend) in the project root and move the old pair to `legacy/`. Make the no-legend copy: `python overlay-tools/strip_legend.py NEW.png legacy/OLD.png "legacy/OLD No Legend.png" "Overlays/NEW No Legend.png"`. It takes the legend's pixels (wherever the old pair differs, plus anything retyped next to them, e.g. the colophon date, which sits straight on the terrain) from the old no-legend map and everything else from the new map, so no Affinity export is needed unless the legend panel itself moved or grew (it prints how many changed pixels it could not place).
2. Point `GEO_MAP` in `build_overlays.py` and `GEO_MAP` / `GEO_MAP_NO_LEGEND` in `build_layers.py` at the new files; run `build_layers.py`, then `build_overlays.py`.
3. Diff old and new maps by pixel (cluster the differences, crop each, look) and read the cartographer's change notes against it. Then `git diff src/data/traced-areas.json`: every nation whose traced area moved is one to check. What the 2026-10-03 issue needed: new borders have holes where labels, flags and rivers cross them (`border_course.py` along the new line, patches in `border-patches.json`), a 1-px hole where a new border meets an old one, and **a border that was removed from the map is still a white line on `Eurth Blank Map Borders.png`**, so the nation stays split in two: trace the blank map's own line (it can run 20-50 px from where the red line was) into `border-erasers.json`. Seeds of a new nation go on the side of the border the nation is on, not under its label (Tetlacatian's label and flag sit outside its territory, in the unassigned interior). Only the coastline and the lakes come from the blank map; a re-issue that redraws a coast needs that PNG edited too (the 10-3-2026 issue changed none; Tavok's islands only had their terrain and labels redrawn). Where the blank map's water is simply wrong, rewrite that window of the PNG from the geography map by script: water = the light water fill plus the dark outline next to it, so rivers stay land (done 2026-10-03 for the lake on Tavok's mainland, window 2080-2142 x 2893-2968, which the blank map had 10 px too far north-east, with an outlet channel to the sea that the geography map draws as a river).
4. Nations removed by the issue: take their seeds and flag box out, drop them from `nations.js` and `manual-edits.json`, and keep their entry in `legacy/removed-nations.md` (Leimurya, 2026-10-03). A renamed territory keeps its row: the island labelled Astrini is now labelled Niederoestereich (same flag, same city Ranke, which the secondary data already had as Niederoestereich's capital), so Astrini's seeds and colour moved to that key and Astrini is archived too. New nations: `create_nation` in `data-tools/nations_file.py` (Kalei; Tetlacatian with `npc: true`), a seed, a snapped flag box and a colour. A flag redrawn on the map (Bamraland) needs a new box and usually a new colour; a flag that vanished from the map (Korinon, Parvaquilee) loses its box but keeps its territory and colour.
5. Update this file, `nation-colors.md` and the memory notes, commit, deploy.

## Nation Data Sources

```bash
python data-tools/fill_from_secondary.py   # fill null/missing fields and missing nations from the secondary CSV (safe to re-run)
python data-tools/compare_sheet.py [export.xlsx]  # Google Sheet vs nations.js -> nation-data/Countries on Eurth vs map.xlsx. No argument: the stored CSV; with the Excel export: rewrites the CSV from it first
```

Three tiers: manual > primary > secondary. **Manual** = anything the user typed into the review page (stats, colour, a created nation). It is written into `nations.js` and recorded as `{key: {field: value}}` in `nation-data/manual-edits.json`, which is authoritative: the field leaves `secondaryFields`, the secondary fill never touches it (a manual `null` means unknown, not a gap), and `fill_from_secondary.py` puts the manual value back if `nations.js` no longer has it (`apply_manual_edits`). When updating `nations.js` from a forum paste or the spreadsheet, check `manual-edits.json` first: a field listed there must be changed there too (or removed from it), or the next fill run reverts it. **Primary** = what the user gave and vetted (spreadsheet, forum pastes). **Secondary** = `Secondary Country Data.csv`, the table from the iiwiki Eurth main page, kept as the five columns the fill reads (Country, Capital, Area, Population, GDPPC); its figures are often older and lower, so it ranks below the other two. Secondary data only fills gaps: a null/missing field, or a nation missing from `nations.js`. It never replaces an existing value, and every field it filled is listed in that nation's `secondaryFields`. When the user supplies a vetted value for such a field, update it and remove the field from `secondaryFields`.

`nation-data/` (written by the script): `nations-primary-snapshot.json` is `nations.js` as it was before the first fill (written once, never overwritten); `nations-current.json` is the same dump now — diff the two to see exactly what secondary data added; `secondary-fill-report.md` lists the filled fields, the added nations, and every place secondary disagrees with a kept value.

## Suggested edits

Viewers can propose a correction without touching the data: "Suggest an edit" in the nation panel opens `SuggestEditForm.jsx` with the five stored stats (full name, capital, population, GDP per capita, land area; GDP is derived so it is not offered) plus an optional handle and a source/reason note. Only the fields whose parsed value differs from `nations.js` are sent; clearing a box proposes `null` (unknown). For the nations in `map-area-nations.json` the panel shows the traced area, but the form edits the stated `landArea` and says so.

`api/suggest.js` (`POST /api/suggest`, body `{key, fields, handle, note, website}`) re-validates everything server-side (known key, known fields, text ≤ 120 chars, numbers finite and within caps, at least one real change, body ≤ 10 KB) and then files a **GitHub issue** on `a-seth-harrison/eurth-map` (or `SUGGEST_GITHUB_REPO`) with the label `suggested-edit`: a `Field | Current | Proposed` table of the changed fields, the handle, the note, a note of which current values come from the secondary source, and last a fenced ```json block `{"key": ..., "fields": {...}}` that the apply script reads. Spam guards are stateless: the request's Origin/Referer host must be the map itself (else 403), and a filled honeypot field `website` is answered with a fake OK. "The map itself" (`originOk`) is the host the request was served on (`x-forwarded-host` / `host`), the hosts Vercel reports for the deployment (`VERCEL_URL`, `VERCEL_BRANCH_URL`, `VERCEL_PROJECT_PRODUCTION_URL`), `eurth-map.vercel.app` and its `eurth-map-*` previews, localhost, and anything in `SUGGEST_ALLOWED_HOSTS`; so a fork under another project name or a custom domain works without a code change (since 2026-09-28).

- `SUGGEST_GITHUB_TOKEN` — fine-grained GitHub PAT, repository access only `a-seth-harrison/eurth-map`, permission Issues: read and write. Stored as a Vercel env var (`vercel env add SUGGEST_GITHUB_TOKEN production`, then redeploy), never in git. When it expires GitHub answers 401, the function logs it and viewers see "Could not file the suggestion"; rotate with `vercel env rm` + `vercel env add`. Without it the function returns 503.
- `SUGGEST_GITHUB_REPO` — optional `owner/name` the issues are filed on, for a fork; without it the default in `api/suggest.js` is used. `data-tools/apply_suggestion.py` reads the same variable from the shell.
- `SUGGEST_ALLOWED_HOSTS` — optional, comma-separated hostnames allowed to post besides the ones above. Only needed when the site is served through a proxy (the browser's host is then not the host the function sees).
- `SUGGEST_DRY_RUN` — any value: log the would-be issue to the console and return `issues/0` with `dry: true` (the form says "dry run — nothing was filed"). Set in `eurth-map/.env` for `vercel dev`. `.env` is gitignored and in `.vercelignore`.
- The label was created once with `gh label create suggested-edit`; the API would also create it on first use.

Reviewing is done with `gh` logged in as the owner:

```bash
python data-tools/apply_suggestion.py              # list the open suggestions
python data-tools/apply_suggestion.py 12           # show #12's current -> proposed values, ask, apply, close the issue with a comment
python data-tools/apply_suggestion.py 12 --only population --yes --keep-open   # a subset, no prompt, leave it open
```

Applying goes through `nations_file.save_nation`, so the fields become manual edits (recorded in `manual-edits.json`, so the secondary fill never reverts them). The script warns when a field's current value is no longer what the issue's table shows, since the suggestion was made against older data. Rejecting is just closing the issue on GitHub.

## Map Layers

```bash
python overlay-tools/build_layers.py      # rebuild public/background.{png,webp}, public/layers/*.webp, apple-touch-icon.png, src/data/map-layers.json (~1 min)
```

Three toggleable overlays (bottom left): Climate, Ocean currents, Tectonic plates. (A fourth, a drawn 15° Grid, was removed 2026-09-21 because the base map already prints the graticule.) Re-run the script when any file in `Overlays/` or the geography map changes.

- The base map has no legend. The legend is its own image layer, positioned at the box where the legend and no-legend geography maps differ: the geography legend normally, the climate legend (from `Eurth-Climate-Key.png`) while Climate is on.
- The script makes the source art overlay-friendly and **bakes the opacity into the images** (constants at the top of the script): climate = sea and its built-in legend made transparent, zones at 50%; currents = only the arrows and names kept (colour un-mixing against the sea/land colours, so anti-aliased edges stay clean); tectonic = plates as a 45% tint with the black boundaries and names at 90%.
- Formats: the base map is lossy WebP (`BASE_MAP_QUALITY` = 90, labels checked against the PNG), overlays and legends are lossless WebP. Overlays wider than 4000 px (only climate) also get a `-half.webp` copy; `src/data/layers.js` picks it when `IS_PHONE`. The base map is full size on every device (the text is what people read) and has no half copy (removed 2026-10-02). The CSS lays every layer out at 8000x4000 whatever its resolution, so nothing else depends on the choice. Half copies of the overlays use nearest-neighbour: smoothing flat colours made the lossless file ten times larger.
- Flat map: the layers are stacked `<img>`s inside `.map-transform`. Globe: globe.gl takes one texture, so `GlobeViewer.jsx` flattens base + overlays + legend into a canvas (`composeTexture`, 8000 px wide capped to the GPU's max texture size; if Safari refuses a canvas that large — no context, or a transparent centre pixel — it retries at 4000) and swaps the globe material's map. The canvas is emptied once the texture is uploaded (`texture.onUpdate`) to free its memory. The texture is sampled with a mipmap bias (`TEXTURE_LOD_BIAS`, patched into the material's shader) so small text is less soft when zoomed out; the full-width texture on touch devices is what fixed the text when zoomed in.
- **Climate readout** (added 2026-09-25): while Climate is on, the pointer's zone is named, e.g. "Dfa - Humid Continental (Hot Summer)" (the legend's wording), in both viewers. A mouse gets it in the tooltip next to the cursor (`HoverTooltip.jsx`, which also carries the hovered nation's name; the old fixed bottom-centre bar is gone). A finger gets it by **long press**: held still for 350 ms (`LONG_PRESS_MS`) the readout appears above the finger (tablets; on phones, `IS_PHONE`, only the card shows it, since the screen is too small for both: `HoverTooltip.jsx` drops the zone there), sliding the finger scrubs instead of panning (on the globe the OrbitControls are switched off for the gesture, and the click the browser sends afterwards is suppressed), lifting leaves it pinned until the next touch. A **climate card** (`ClimateCard.jsx`, top centre; under the Measure button on narrow screens) shows the last zone read with a Wikipedia link, and keeps it while the mouse is off the map so the link can be clicked. The zones come from `src/utils/climate.js`: `climate-half.webp` (4000x2000, what phones already display) is drawn to a canvas once, each pixel matched to the nearest colour in `src/data/climates.js` (0 = sea / legend box / no match), kept as an 8 MB byte grid, canvas freed; loaded the first time Climate is switched on. The 19 colours are the climate map's exact paint; `build_layers.py` prints them after building the overlay, so a repainted map has to be carried into `climates.js`.

## International organizations

An organization is an overlay switch (bottom-left box, "Organizations" group, with a colour swatch): while it is on, every member is lit in the organization's colour without hovering, in both views. The toggle shares the `overlays` state object in `App.jsx` with the image overlays, keyed by the organization's `id`; `imageLayers()` ignores ids it does not know, and `GlobeViewer.jsx` keys its texture memo on the image overlay ids alone so an organization toggle never recomposes the 8000 px texture.

- **Shared members are striped**: a nation in two or more enabled organizations is filled with diagonal stripes of their colours, in the order the organizations are listed (`memberColors()` returns `{nationKey: [colour, ...]}`; one colour = plain fill). One set of stripes spans `STRIPE_PERIOD_DEG` (4°) of longitude minus latitude in both views, so the two views draw the same stripes; the value must divide 360 or the globe shows a seam at 90°W. Flat map: a repeating `<linearGradient>` with hard stops, made on first use in the overlay SVG's `<defs>` (`stripeFill` in `MapViewer.jsx`) and handed to the CSS through `--org-color` as `url(#...)`; a `<pattern>` was avoided because its tiles show hairlines. Globe: `src/utils/stripeMaterial.js` patches a `MeshBasicMaterial` to pick the colour from the fragment's own lon/lat and returns it through `polygonCapMaterial`, which globe.gl uses instead of the cap colour; materials are cached per colour set and opacity and disposed with the globe. Hover (70%) and selected (red) work as for any member. The stripes are in map units, so they grow with zoom. Aurora's shape has its own inner transform: if it ever joins two organizations, check its stripes on the flat map.
- **Highlight rule**: idle member = organization colour at 60% (`.org` in `App.css` and `ORG_OPACITY` in `GlobeViewer.jsx`, keep the two equal); a member under the cursor = the same colour at 70% (`.org.hovered:not(.selected)`, `ORG_HOVER_OPACITY`; red on hover was too strong); a selected member = the plain default red (`#d81e1e`) at the usual 50%. The nation's own colour is never used for a member, so two highlights never blend. Non-members behave as before.

## Touch and small screens

- **Input is Pointer Events in both viewers**, so mouse, finger and pen share one path. Flat map: one pointer pans, two pinch-zoom about their midpoint (`zoomAt`, shared with the wheel); a pinch never ends as a tap. All view changes go through `updateTransform`, which updates `transformRef` at once (several pinch events can arrive per frame) and applies `clampPan` (see Flat map wrap-around). A tap tolerates 10 px of wobble, a mouse click 5.
- **Hover is mouse-only** (`pointerType === "mouse"`) in both viewers: browsers and globe.gl report a hover on every tap, which left the highlight behind. The same goes for the measure live preview. On touch, the selected highlight and the panel are the feedback; the nation name never shows in the tooltip. The one touch gesture that brings the tooltip up is the climate long press (see Map Layers): the press timer starts on `pointerdown`, is cancelled by movement past the tap threshold, a second finger or the lift, and while it is active `pointermove` scrubs the readout instead of panning. Both viewports swallow `contextmenu` so Android's long-press menu stays away.
- **Fit to screen**: a `ResizeObserver` in `MapViewer.jsx` opens the map centred at the scale that fits the whole world, but never under half the viewport height (upright phones). Minimum zoom is `min(0.5, fit)`, so the whole world is always reachable. A resize or rotation keeps the centre in place. The globe also follows its container with a `ResizeObserver`.
- **Layout (`App.css`, end of file; variables in `index.css`)**: `@media (pointer: coarse)` = 44 px controls (including the suggest form's inputs and the climate card's link, at 16 px text so iOS does not zoom into them). `max-width: 600px` = the nation panel is a bottom sheet (max 45% of the height); `MapViewer.jsx` glides the map up when the tapped nation would be behind it (and lets the vertical limit follow the sheet, see Flat map wrap-around). The suggest form is a native `<dialog>` in the top layer, so the sheet's height cap does not apply to it; `index.css` zeroes every margin, so it sets `margin: auto` itself to stay centred. The overlay list folds behind its "Overlays" title on **every** screen (`LayerToggles.jsx`, since 2026-09-27: with seven organizations the open list covered the south-west continent); it starts folded where `max-width: 600px` or `max-height: 500px` and open elsewhere, the title shows an arrow and, while folded, how many switches are on ("Overlays · 2 on"). Inside it, the organizations have their own fold (since 2026-10-02), closed on every screen at load: what shows is the three image overlays, "Display all organizations" and a "Choose organizations (8)" button (`.org-list-toggle`) that opens the one-by-one list ("Hide the list" closes it; folded with only some on it adds "· 2 on"). The open list stops under the Measure button and scrolls, since it grows with each organization. Heights use `100dvh`, fixed controls sit at `--edge-*` = `max(16px, env(safe-area-inset-*))`, and the layer switches are placed from `--control-h`, so change that if the view switch changes height.
- **Memory is the constraint on iOS**, not download size: an 8000x4000 image is 128 MB decoded. Since 2026-09-22 every device loads the full-size base map and the full 8000 px globe texture (at half size the text was visibly soft; the owner puts base-map quality above the overlays); phones still get the half-size climate overlay. Checked fine on an iPad and the owner's phone. If a device reloads the tab from memory pressure, shrink the globe texture or the overlays first, not the base map.
- **Testing**: the Browser pane's mobile preset emulates the size and a coarse pointer, but its clicks arrive as mouse events. Test pinch, taps and the long press by dispatching `PointerEvent`s with `pointerType: "touch"` on `.map-viewport` / `.globe-viewport` (never on `window`: the handlers call `contains(e.target)`); the pane's screenshots are scaled, so take event coordinates from the page, not the image. Checked on a real iPad 2026-09-22: the 8000 px globe texture loads and looks sharp. Not yet checked on real hardware: iOS memory behaviour with all overlays on, phones, and the climate long press.

## Flat map wrap-around

- **Sideways the world repeats**, like Google Maps. `.map-transform` holds three `.map-world` copies (base map + image layers) at -8000 / 0 / +8000 px (`WORLD_COPIES`); the same `<img>` src three times is decoded once. `clampPan` wraps `transform.x` by whole world widths so the viewport's centre is always over the middle copy; that covers any viewport up to 4:1 at minimum zoom.
- **Nation shapes**: the overlay SVG's viewBox is widened to the three worlds and every nation group is cloned into the two side copies. Originals keep their `id`; originals and clones all carry `data-nation`, and clones have their ids stripped. Hit-testing (`findNation`), the highlight classes and the CSS all go by `data-nation`, never by id, so a nation lights up in every copy. Aurora needs nothing special: `cloneNode(true)` keeps its inner transform.
- **Measuring**: `toMapPoint` wraps x into 0-8000, so points are ordinary map pixels whichever copy was clicked and `useMeasurement` is unchanged. Lines, labels and points are drawn once per copy; each area fill is drawn once per offset from -2 to +2 worlds, outside those groups, so no two fills stack.
- **Up and down the view stops at the map's edges** (no scrolling into the background). A map shorter than the viewport sits centred and does not move vertically. While the phone's bottom sheet is open, `sheetHeight` is taken off the viewport height for this, so the map can rise above the sheet and re-centres in the space that is left; it settles back when the sheet closes.

## Key Design Decisions

- SVG over Leaflet: chosen for simplicity since the only interactions are hover/highlight/click — no tile layers or geographic projections needed
- SVG loaded via fetch + DOMParser (not as React component) so we can use `getElementById` and direct DOM manipulation for performance
- Suggested edits go to GitHub issues rather than a database or email: no new service, the owner gets notifications and a structured record, and the JSON block in each issue keeps a scripted apply possible later
- Pan and pinch use window-level pointermove/pointerup (not pointer capture) to avoid stealing events from SVG paths
- Nation groups have `opacity: 0` and `visibility: hidden`, and their paths `pointer-events: all` (which ignores visibility), so they are not painted but hittable; group opacity transitions on hover/select (group-level so overlapping paths do not darken). The visibility matters for speed (since 2026-10-02): at opacity 0 alone the browser redrew all ~400 shapes at every zoom step. The globe does the same thing its own way: an unlit nation's cap gets `HIDDEN_CAP`, a material with `visible: false`, which three.js does not draw but still raycasts, and polygons have no sides or stroke. With a clear colour instead, the globe made 1,567 draw calls a frame (20 ms of CPU); now 2 plus the lit nations
- Currency is "A$" (Adaptus Solidus), equivalent to USD

## Data Formatting Rules (from spreadsheet notes)

- Population: always displayed as X.X million (e.g., 147478008 → "147.5 million")
- GDPPC: rounded to nearest A$500 for display, but GDP computed with unrounded value first
- GDP: two decimals when in trillions ("A$1.90 trillion"), whole number when in billions ("A$866 billion")
- Land area: rounded to nearest 1,000 km²
- iiwiki link pattern: `https://iiwiki.com/w/[id]` (underscores for spaces)

## Geography facts (for measurement / globe work)

- The map is a plain equirectangular (plate carrée) projection of a globe the same size as Earth (R = 6371 km): 8000x4000 px = 360°x180°, so 22.22 px per degree. Verified against the graticule labels on the map (165°W sits at x ≈ 335) and by the area check in `build_overlays.py` (median 25.4–25.9 km² per latitude-weighted pixel vs 25.09 expected at the equator).
- Pixel to lon/lat: `lon = x / 8000 * 360 - 180`, `lat = 90 - y / 4000 * 180`.
- Never measure in pixels. Distances = great-circle (haversine); areas = spherical polygon area. Pixel distances are only right along the equator.
